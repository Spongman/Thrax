This variant runs the Cortex-M0 ARMv6-M Thumb integer instruction set. It uses the existing ARM target id `armv8` and setting `executionState: 'cortex-m0'`; AArch64 and AArch32 keep their existing settings and behavior.

The instruction encodings and semantics follow [Arm's Cortex-M0 Devices Generic User Guide, DUI 0497A](https://documentation-service.arm.com/static/5ea6ce5e9931941038def8c1) and [the Cortex-M0 instruction summary](https://support.arm.com/documentation/ddi0432/c/programmers-model/instruction-set-summary?lang=en). Tests check independent encoded halfwords, BL, special-register transfers, arithmetic flags, stack operation, PC-relative addressing, load widths, fault rollback and rewind.

Supported instructions include integer arithmetic/logic/shifts, conditional and unconditional branches, BX/BLX registers, 32-bit BL, ADR and literal loads, byte/halfword/word transfers, signed loads, LDM/STM, PUSH/POP, extension/reversal, MRS/MSR, CPS, barriers and hints. Thumb-2 integer extensions, IT, CBZ/CBNZ, floating point and DSP instructions are rejected. Undefined or unpredictable forms fault rather than silently executing a guessed behavior.

The assembler accepts a GNU unified Thumb subset, including named labels, `.include`, `.equ`, `.set`, section/data/string directives, alignment, and `ldr rN, =expression` literal pools (`.ltorg`, `.pool`, or the automatic end pool). `.thumb_func` marks function pointers in emitted data with bit 0 set while source/navigation labels remain even. There are no assembler macros, numeric local labels, relaxation, relocatable object files, armasm directives or automatic instruction widening. Use explicit flag-setting names such as `adds` and `movs` where required by unified Thumb syntax.

The teaching machine starts in privileged Thread mode at `_start`, `main`, or 0x00400000, with data at 0x00420000 and an aligned descending stack at the selected RAM limit. It loads addressed program bytes directly; it does not boot a device vector table. This flat RAM layout matches the workbench ARM variants, rather than a particular microcontroller. MSP, PSP, SPSEL in CONTROL, PRIMASK, NZCV and the Thumb execution bit are represented. Cortex-M0 CONTROL bit 0 is reserved; there is no unprivileged mode. MRS reads of EPSR return zero, as specified, while the debugger's XPSR exposes the Thumb bit. Halfword/word data accesses require alignment.

There is no NVIC, SysTick, hardware exception entry/return, interrupt/event delivery, peripheral model or cycle-accurate timing. Accessing unavailable memory/peripherals, exception return and WFI fault explicitly. SEV sets the local event register; WFE consumes a set event, otherwise faults because an external wakeup is unavailable. Barriers are ordering no-ops on this synchronous single-core machine; YIELD and NOP are hints. BKPT halts after the instruction in this debugger.

SVC uses an explicit teaching console ABI, **not Linux or hardware exception delivery**: `svc #0` halts, `#1` prints the signed integer in R0, `#4` prints a NUL-terminated byte string addressed by R0, `#5` waits for a signed integer and places it in R0, and `#11` prints R0's low-byte character. Other SVC numbers fault. Console input acceptance, output, memory, register and call-frame changes can be rewound.

History uses the shared typed block allocator and its 256 MiB typed-buffer limit, with an explicit M0 schema. Call-stack changes use constant-size typed deltas. Source gutters cap long data declarations to four rows. Execution yields after bounded batches (20,000 instructions or 16 ms), including when no source instruction matches the current pacing filter. Stop, disposal and speed changes are checked across yields.
